# KFACS Oral Functional Reserve & Mortality — Code Package

Analysis scripts for the KFACS study of oral functional reserve, functional dentition, and all-cause mortality in community-dwelling older adults. The package contains Python and R implementations for reproducibility and cross-checking of analytical results.

## Repository contents

### Python workflow

The Python workflow builds the analytic datasets from the raw KFACS source files and generates the main and supplementary analyses.

Run `00_setup_and_mice.py` first. Set `DATA_DIR` near the top of the script to the directory containing the required source datasets:

- `_최종_2016_2024_KFACS.xlsx`
- `_최종_2016-2020_통합자료_치과_v20230904_LYH.xlsx`
- `TalkFile_outcome_w1w5.xlsx`
- `KFACS_추적조사상세_최종_260608__2_.xlsx`

The setup script creates the intermediate datasets used by the remaining Python scripts:

- `baseline.pkl`
- `final_preMI.pkl`
- `mi_long_v2.pkl`
- `landmark_cohort.pkl`
- `physical_measures.pkl`
- dental extract `.pkl` files

Helper modules:

- `coxph.py` — Cox proportional hazards regression with Efron handling of tied event times
- `pooling.py` — Rubin-rule pooling across multiply imputed datasets
- `km.py` — Kaplan–Meier estimator

Main-analysis scripts:

- `table1_code.py`
- `table2_code.py`
- `table3_code.py`
- `figure1_code.py`
- `figure2_code.py`

Supplementary-analysis scripts:

- `etable1_code.py`
- `etable3_code.py`
- `etable4_code.py`
- `etable5_code.py`
- `etable6_code.py`
- `etable7_code.py`
- `efigure1_code.py`
- `efigure2_code.py`
- `efigure3_code.py`

`efigure1_code.py` and `efigure2_code.py` require the intermediate datasets generated by `00_setup_and_mice.py`. `efigure2_code.py` also uses `coxph.py` and `pooling.py`. `efigure3_code.py` requires `table3_output.csv`, generated by `table3_code.py`.

### R scripts

The repository currently includes the following R implementations:

- `Figure 2.R` — Kaplan–Meier survival estimates
- `Figure 3.R` — deficit-based dose-response analysis (eFigure 2)
- `eFigure 3.R` — sequential pathway attenuation analysis
- `eTable 8_B200_UnoC_bootstrap_validation.R` — B=200 bootstrap internal validation using Uno's C statistic

For these scripts, place `KFACS_analytic_dataset_MICE_v2.xlsx` in the working directory or edit the data-path variable near the top of the script.

## Implementation notes

- The Python Cox model uses Efron handling of tied event times and Newton-Raphson optimization.
- The Python multiple-imputation workflow uses `sklearn`'s `IterativeImputer(sample_posterior=True)` with Bayesian ridge regression. R analyses based on a pre-built MICE export may differ slightly because the imputation procedures are not identical.
- `physical_frailty_burden_no_weight_loss` is calculated as `chs_total - weight_loss_flag`; `chs_total` is the sum of the five CHS frailty components.
- Death-ascertainment source (telephone call, center visit, or home visit) is not reported because the available per-wave response codes do not contain a death indicator.
